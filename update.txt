## 2. ASYNC VIDEO — REPLACE ZOOM ENTIRELY

Remove all interview slot booking, Zoom link sending, and reminder emails for Zoom. Replace with browser-based async video recording built into the platform.

### Video Recording Page (/video/[token])

After quiz submission, the thank you screen shows:
"One more step — record a short video introduction"
With a button: "Record my video →" linking to /video/[token]

The video page:
- Uses the browser MediaRecorder API to record directly from webcam + microphone
- Shows 3 questions one at a time, 90 seconds max per answer
- Questions are role-specific, pulled from a new video_questions table in Supabase (seed with questions per department — see below)
- Shows a countdown timer per question
- Allows one retake per question
- On final submit, uploads the recorded video blob to Supabase Storage bucket: videos/ (private)
- Stores video metadata in a new videos table
- After upload: applicant stage moves to assessment_video_done
- Shows a final screen: "Thank you [First Name]. Our hiring team will review your application and be in touch if your profile matches what we're looking for."
- Sends a "thank you / under review" email immediately via Resend

### Video Questions (seed into Supabase)

Create a video_questions table:
```sql
create table video_questions (
  id uuid primary key default uuid_generate_v4(),
  department text not null,
  question text not null,
  order_index integer not null,
  max_seconds integer not null default 90
);
```

Seed with 3 questions per department (engineering-backend, engineering-frontend, engineering-ai, engineering-security, engineering-devops, product-design, operations). Questions should be:
1. "Walk us through a project or piece of work you're genuinely proud of. What was hard about it and what did you learn?"
2. A role-specific technical or craft question
3. "Why KoreLabs specifically — what about this problem space excites you enough to want to work on it every day?"

### Videos Table
```sql
create table videos (
  id uuid primary key default uuid_generate_v4(),
  applicant_id uuid not null references applicants(id) on delete cascade,
  question_index integer not null,
  storage_path text not null,
  duration_seconds integer,
  created_at timestamptz not null default now()
);
```

Create a private Supabase Storage bucket called videos.

### Video Playback in Admin

On each applicant's profile page, add a Videos tab. For each recorded video:
- Show the question text
- Show a video player using a signed URL from Supabase Storage (1 hour expiry)
- Show duration

## 3. RE-ENGAGEMENT SYSTEM

The system automatically follows up with stuck applicants. All re-engagement emails send via Resend scheduledAt — no cron needed.

### Rules:

**Stuck at assessment_sent (haven't taken quiz):**
- 48 hours after assessment email sent → Nudge 1: warm reminder that their quiz link is still open
- 5 days after assessment email sent → Nudge 2: "This is your last reminder — your link expires soon"
- After Nudge 2 → move to archived automatically, no more emails

**Stuck at assessment_video_done (video done but no movement):**
- No automated email — hiring manager handles this stage manually

**Implementation:**
When the assessment email is sent in /api/apply, immediately schedule both nudge emails via Resend scheduledAt at T+48h and T+5days. Store the Resend scheduled email IDs in a new field on the applicant record so they can be cancelled if the applicant completes the assessment before the nudge fires.

Add to applicants table:
```sql
alter table applicants add column nudge1_resend_id text;
alter table applicants add column nudge2_resend_id text;
```

When applicant completes assessment, cancel both scheduled nudge emails via Resend API (DELETE /emails/{id}) so they never receive a nudge after completing.

### Re-engage existing applicants

Write a one-time migration endpoint at /api/admin/reengage-all (protected by admin auth) that:
1. Finds all applicants currently at assessment_sent with no completed assessment
2. Sends them a fresh assessment email immediately with a new or existing quiz token
3. Schedules their nudge emails
4. Returns a count of how many were re-engaged

## 4. HIRING MANAGER HANDOFF

When the hiring manager reviews an applicant and wants to pass them to the next step, they have two options in the admin:

### Single applicant handoff
On each applicant profile, a "Send to Hiring Manager" button that:
- Calls POST /api/admin/notify-hiring-manager with the applicant ID
- Sends a rich email to ADMIN_NOTIFY_EMAIL containing:
  - Applicant name, role, location, LinkedIn, GitHub, portfolio
  - Their "Why KoreLabs" response
  - Quiz score breakdown (total, fundamentals, applied, KoreLabs tier)
  - Signed CV download link (24h expiry)
  - Links to their video recordings (signed URLs)
  - Admin profile link
  - A clear subject: "Applicant ready for review — [Name] · [Role]"
- Updates applicant stage to under_review
- Shows success confirmation in the UI

### Bulk handoff
On the Applications list page, checkboxes on each row. A "Send selected to hiring manager" button appears when any are checked. This:
- Calls POST /api/admin/notify-hiring-manager with an array of applicant IDs
- Sends ONE consolidated email to ADMIN_NOTIFY_EMAIL with all selected applicants listed cleanly
- Each applicant section in the email contains the same info as the single handoff
- Subject: "Batch review — [N] applicants ready · KoreLabs"
- Updates all selected applicants to under_review

Add to .env:
```
ADMIN_NOTIFY_EMAIL=
```
